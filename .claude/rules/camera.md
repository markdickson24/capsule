## In-App Camera (`CameraScreen.tsx`)

- `mode="video"` required on `CameraView` even for photos — expo-camera 17.x needs it for `recordAsync`.
- Tap = photo, hold 300ms = video (manual `setTimeout`, not `onLongPress`).
- Double-tap (within 300ms) switches front/back camera.
- Pinch (`PanResponder`): zoom 0–1, shown as 1×–5× badge, fades after 800ms.
- Max recording: 2 minutes (`MAX_RECORD_SECONDS`).
- **Hands-free lock:** hold-to-record, slide the shutter finger right ≥ 90px — lock pill highlights + pulses (`lockAnim`); release to lock (shutter becomes a red stop square, tap to end). Works for single + dual. State: `locked`, `lockedRef`, `willLockRef` + `hasFiredLockHapticRef`, all reset in `cleanupRecording`.
- **Zoom deadzone:** horizontal movement ≥ 20px (`LOCK_DEADZONE_X`) suppresses vertical zoom during a rightward lock-swipe.
- **First-run gesture coach:** full-screen overlay ("Tap for photo · Hold for video · Slide right to lock") once per install, gated on `cap_camera_coach_seen` AsyncStorage (same pattern as `sessionStore.markOnboarded`/`wasOnboarded`); tap dismisses + sets the flag.
- **Idle hint retires after use:** "Tap for photo · Hold for video" hides after `HINT_HIDE_AFTER` (3) captures, tracked via `cap_camera_captures` AsyncStorage, incremented in `goToPreview()`. Recording-state copy always shows; a space keeps row height stable.
- **Flip camera mid-recording (single-camera only):** tap the reverse button or double-tap the viewfinder — a multi-segment loop in `startRecording`: each `recordAsync` call is one segment; `flipCameraDuringRecording()` sets `pendingFlipRef`, stops the segment, calls `setCameraMode`; `useEffect([facing])` resolves the await on re-render. Segments stitch via `stitchVideos()` (`modules/expo-video-stitcher`) before Preview. 2-minute cap shared across segments (`recordSecondsRef`); dual mode excluded.
  - **iOS orientation gotcha:** `ExpoVideoStitcherModule.stitch()` builds an `AVMutableComposition` with one shared video track — only one `preferredTransform` for the whole timeline, so front/back segments with different orientations can't both render correctly. Fixed via an explicit `AVMutableVideoComposition` with one instruction per segment, each applying its own `preferredTransform` (re-anchored, scaled/centered into a shared canvas — also guards differing native resolutions). Android has the same bug (`MediaMuxer`'s single track, `stitch()` only registers the first segment's rotation) — needs a real decode/rotate/encode transcode, not yet fixed.
- Photos: resized to 1920px via `resizeForUpload()` (`src/lib/imageResize.ts`, shared with the upload queue), compress 0.82, quality 0.88.
- Front camera photos mirrored by `mirror={facing === 'front'}` on `CameraView` — flips both preview and JPEG natively (iOS sets `isVideoMirrored` on the photo connection; Android flips the bitmap in `ResolveTakenPicture`). Do **not** add a JS-side `FlipType.Horizontal` pass for front photos — composes with the native mirror back to identity (tried and reverted).
- `useIsFocused()` stops camera rendering when the tab isn't active.
- Navigates to `Preview` with `{ uri, mediaType, facing }`.

**Camera mode dropdown:** `styles.modeDropdown` selects `cameraMode: 'back' | 'front' | 'dual'`; `facing` derives from it. `Back`/`Front` render `CameraView`; `Dual` renders `<DualCameraView>` (only when `isDualCameraSupported`). Dual mode disables pinch/zoom + double-tap-flip, hides the reverse button. Tap = dual photo; hold 300ms = dual video.

## Dual Camera (`modules/expo-dual-camera`)

Simultaneous front+back capture, two layouts — `sideBySide` (both feeds aspect-fit over a blurred backdrop) and `pip` (full back + rounded front bubble). `expo-camera` can't do multi-cam, so this is a **local Expo native module** (autolinked from `modules/`, survives `expo prebuild --clean`): `import { DualCameraView, isDualCameraSupported, DualCameraViewRef, DualCameraLayout } from '../../../modules/expo-dual-camera'`.

- **Layout prop:** `<DualCameraView layout="sideBySide" | "pip" />`. `CameraScreen` holds `dualLayout` state + a live Split/PiP switcher (`styles.layoutSwitch`); native `setLayout` re-runs `layoutSubviews` and picks the matching compositor — instant, dims during recording.
- **iOS (`ios/ExpoDualCameraView.swift`):** `AVCaptureMultiCamSession`, back+front inputs via `addInputWithNoConnections` + explicit `AVCaptureConnection`s. Two `AVCaptureVideoPreviewLayer`s per `layout` (`videoGravity = .resizeAspect` half-boxes for sideBySide; full back + corner bubble for pip). **sideBySide backdrop:** a `backdropLayer` (`CALayer`) behind both previews, fed by the back lens's `AVCaptureVideoDataOutput` (`onFrame(isBack:)` downscales ~96px, `CIGaussianBlur`s, sets `backdropLayer.contents`, ~14fps) — no new `AVCaptureConnection`. Hidden in `pip` (back layer fills via `.resizeAspectFill`). **Capture: each lens runs an `AVCaptureVideoDataOutput` (`FrameGrabber`), NOT `AVCapturePhotoOutput`** (AVMultiCamPiP/Snapchat pattern). `capturePhoto()` arms a grab; each lens's next frame converts via a shared `CIContext` to a `UIImage`, merged by `composeSideBySide` (blurred backdrop, each lens drawn whole via `drawAspectFit`, no divider) or `composePiP` (rounded, bordered, inset) into one JPEG. Front lens mirrored at the capture connection (data connection `.portrait`). 2s timeout if frames never arrive. Resolves `{ uri, width, height }`.
  - **Hardware-cost budget:** the session shares one cost budget across lenses; two `AVCapturePhotoOutput`s blew it (reserve full-res still budget) — hence video-data-output capture. Kept in budget via `applyMultiCamFormat` (binned, modest formats, 24fps cap) and `ensureCanAdd` (steps 24→12fps, retries `canAddConnection`); `reduceHardwareCostIfNeeded` is the post-commit net. Errors report live `session.hardwareCost` (e.g. "cost 1.20").
- **Android (`android/.../ExpoDualCameraModule.kt`):** reports `isSupported = false` (dual-cam is rare/device-specific) — Dual mode hidden.
- **JS (`index.ts`):** guards `Platform.OS !== 'web'` + try/catch around `requireNativeModule`/`requireNativeView`; web/Expo Go fall back to `isDualCameraSupported = false`, `<DualCameraView>` renders null. Native `isSupported` is true only on A12+ iPhones, iOS 13+.
- **Still capture:** `CameraScreen.captureDualPhoto()` → `dualRef.current.capturePhoto()` → same `processPhoto` (resize 1920) + `Preview` nav as single-camera.
- **PiP swap (BeReal-style):** `capturePhoto()` also returns `altUri` (`composePiP(base: front, inset: back)`). Both composites upload: default → `media.storage_key`, swap → `media.alt_storage_key` (`20260616120000_add_media_alt_key.sql`). `PreviewScreen.uploadToSingle(…, altUri?)` uploads both via `uploadFile`. `MediaViewerModal.fetchPhotos` signs both keys; a swap button (`styles.swapBubble`) toggles `swapped[id]`, `shownUrl(item)` picks `altSignedUrl` vs `signedUrl`. sideBySide has no `altUri`; only new dual photos are swappable. Camera→new-capsule `pendingMedia` doesn't carry `altUri` yet (only the single-item `Preview` route does).
- **Video recording:** `recordAsync({ maxDuration })`/`stopRecording()` are view `AsyncFunction`/`Function` on `ExpoDualCameraModule`. `startRecordingWithPromise` sets up `AVAssetWriter` (H.264, 720×1280, 8 Mbps) + `AVCaptureAudioDataOutput` (AAC mono, 44.1 kHz) on `sessionQueue`. `onFrame` stores both lenses' `CMSampleBuffer`s when armed; each back-lens frame composites into a `CVPixelBuffer` from the `AVAssetWriterInputPixelBufferAdaptor` pool, appended with a relative PTS. `recordingLock` (`NSLock`) serialises state across `sessionQueue`/`dataQueue`. ⚠️ **The re-check + `append` must be one locked block, and `finalizeRecording` must hold the same lock across `isRecording = false` and `markAsFinished()`** — appending to a finished `AVAssetWriterInput` raises `NSInternalInconsistencyException` (uncatchable in Swift, aborts the process) if `writeVideoFrame` races `finalizeRecording`'s teardown; `onAudioFrame` had the same defect, narrower window. Compositing runs unlocked; only re-validate-and-append is locked. `finishWriting` stays **outside** the lock. `finalizeRecording` marks inputs finished, calls `finishWriting`, resolves `{ uri }`. Backdrop blur suppressed while recording. No `altUri` for video.
- **`CameraScreen` video flow:** `startDualRecording`/`stopDualRecording` mirror single-camera `startRecording`/`stopRecording` exactly (`isRecordingRef`, `recordInterval`, `maxDurationTimer`, `cleanupRecording`, red-shutter animation). Hold 300ms → `startDualRecording` (`isDualRef.current` check); release → `stopDualRecording`. No `processPhoto` (videos skip ImageManipulator).
- **Requirements:** custom dev/EAS build + physical multi-cam iPhone — not Expo Go/simulator. Uses existing `NSCameraUsageDescription`/`NSMicrophoneUsageDescription` (no app.json change).
- **Not yet device-verified** — errors carry the actual cost number; lower `applyMultiCamFormat`'s `maxWidth` (e.g. 960) and/or starting fps if capture fails.
