# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Capsule** is a time-locked photo-sharing app: members add photos and videos to a capsule that stays locked until a set date (or until everyone is physically together), then it unlocks for all members at once. Live on the App Store (iOS); web is a dev target.

This file is the short core: commands, stack, and the rules that prevent real bugs. Detailed design notes live in `docs/architecture/` (index below). **Read the relevant doc before changing a subsystem**, and update it in the same change.

## Commands

```bash
npx expo start --web        # Run in browser (primary dev target)
npx expo start --ios        # Run on iOS simulator
npx expo run:ios --device --configuration Release   # Release build on a cabled iPhone (phone must be unlocked)
```

```bash
npm run test:lib          # Tier 0: every src/lib/*.test.ts under npx tsx, one process per file, first failure exits 1 (~10s; three boot a throwaway local Postgres)
npm run test:components   # Tier 1: jest (jest-expo/ios + @testing-library/react-native 14); src/**/__tests__/**/*.test.@(ts|tsx) only
npm test                  # test:lib && test:components
npm run typecheck         # tsc --noEmit. Baseline is 0 errors; supabase/functions is excluded (Deno)
```

No linter. CI runs typecheck + tests on every PR.

**Tests:**
- **Prefer Tier 0.** Extract the decision into a pure function in `src/lib/<name>.ts` and assert it in `src/lib/<name>.test.ts`: top-level `import assert from 'node:assert/strict'`, straight-line assertions each commented with the real-world case, closing `console.log('<name>: all assertions passed')`. No `describe`/`it`, no registration. The module must not import `react-native`. Examples: `zoomMath.ts`, `galleryLayout.ts`, `mergeCapsuleUpdate.ts`.
- **SQL fixes (RLS / trigger / RPC)** get a Tier 0 test that boots a local Postgres and loads the real migration SQL — copy `capsulesUpdateColumnGrants.test.ts` or `tombstoneTriggerCascadeDelete.test.ts`. Needs `initdb` on PATH or at `/Library/PostgreSQL/18/bin`.
- **Tier 1 only for real rendering/interaction bugs**: render through `test/renderWithProviders.tsx`, mock `../../../lib/supabase` per file with a `mock`-prefixed chainable builder. Full picture: `audits/BUG_HUNT_2026-09-14.md` § Harness.

**Release:** merging to `main` changes nothing for users. Users only get code through `eas build --platform ios --profile production` → `eas submit` → TestFlight → App Review (OTA updates are off). Supabase changes (migrations, RLS, edge functions) go live immediately and must keep working with **every app build still installed**.

## Rules

Each rule exists because breaking it caused a real bug. The linked doc has the full story.

### Supabase: migrations and production
- `supabase/migrations/` is the source of truth (`supabase-schema.sql` has drifted). Prod's migration history versions don't match repo filenames: check live objects (`pg_policies`, `pg_get_functiondef`), apply through MCP, commit the same SQL as a migration file. **Never `supabase db push`.**
- If a live policy/function differs from its migration, assume live is correct and the migration is stale.
- **No destructive SQL on production** (delete/truncate/drop of app data) without explicit approval from the user in this conversation.
- Changing an RPC's signature: drop the old overload first (else PGRST203), and **re-grant EXECUTE to every role that needs it** — drop+create resets the ACL. `capsule_join_preview` needs `anon` (the join page is signed out).

### Supabase: RLS and grants ([database-and-rls](docs/architecture/database-and-rls.md))
- A membership test always means `joined_at is not null`.
- Never query `capsule_members` inside a `capsule_members` policy — go through a SECURITY DEFINER helper. Policies use `(select auth.uid())`.
- A function called from an RLS policy must stay EXECUTE-granted to the querying role. Check `pg_policy` before revoking anything.
- `users` SELECT is column-granted: never `select('*')`, `email`, `phone` or `push_token`. A new client-readable column needs `grant select (col)` in the same migration.
- Client UPDATE on `capsule_members` and `media` is column-granted (`joined_at`, `live_activity_override`, `caption`). A new client-writable column needs `grant update (col)`.
- `subscription_tier` is written only by `service_role` (`guard_subscription_tier`).
- Create capsules and groups only through `create_capsule_with_owner` / `create_group_with_creator` (atomic; direct INSERT policies are gone).
- Never `.select()` after an insert whose row the SELECT policy can't see yet (e.g. `reactions`); generate the id client-side.
- `notifications` has two FKs to `users`: always FK-qualify the embed (`users!notifications_user_id_fkey`).
- Never delete from `storage.objects` in SQL (`storage.protect_delete` blocks it). Remove blobs client-side through the Storage API, **before** the row delete.
- `superlative_winners` target FKs must stay `ON DELETE CASCADE` (the XOR check makes `SET NULL` fail).
- Don't relax `media` RLS to preload before unlock — surprise mode (default on) depends on it.

### Edge functions and crons ([crons-and-notifications](docs/architecture/crons-and-notifications.md))
- Cron functions authenticate with `requireCronSecret` (`supabase/functions/_shared/cronAuth.ts`), which fails closed. Never write `if (SECRET && …)`. Never expose a secret comparison through a `public`-schema RPC.
- Multi-file deploys need the nested layout (`<fn>/index.ts` + `_shared/cronAuth.ts`). After deploying, POST a wrong bearer: 401 = healthy, 500 = broken.
- Per-minute crons are EXISTS-gated. Sends use claim-and-stamp (`update … where <stamp> is null returning`) and dedupe across overlapping tiers in one run.
- Expo push: chunk ≤100 messages per request. User-authored text goes in the body, never the title.
- `purge-cron-logs` keeps `cron.job_run_details` and `net._http_response` to 7 days (they had grown to 1.8 GB).

### Auth, sessions and deep links ([auth-and-navigation](docs/architecture/auth-and-navigation.md))
- In screens use `sessionStore.get()`, not `supabase.auth.getSession()` (hangs on web with an expired token) and never `getUser()` (network call).
- Native raw uploads use `getFreshAccessToken()` / `getFreshSession()`. A stale token gives `400 jwt expired`; a path/user mismatch gives 403.
- The client is `flowType: 'pkce'`. Never reintroduce implicit-token reset links or `setSession` from a URL.
- The native SecureStore adapter must keep `keychainAccessible: AFTER_FIRST_UNLOCK`.
- Route `capsule://` URLs only through `parseDeepLink` (`src/lib/deepLinkRoute.ts`). Don't use the global `URL` class (RN polyfill breaks custom schemes). Don't add a `linking` prop to `NavigationContainer`.
- A deep link or the join web page never writes membership on its own — it goes through the `JoinCapsuleConfirm` sheet.
- Module-level state (caches, queues, stashes) must be bound to a user id and cleared on sign-out.

### Media and uploads ([storage-and-media](docs/architecture/storage-and-media.md))
- All uploads go through `uploadQueue` (`src/lib/uploadQueue.ts`). Native: `FileSystem.uploadAsync` with both `Authorization` and `apikey` headers.
- **Don't send new images through Supabase's render API.** It bills per distinct origin image (100/month on Pro) and is what pushed the project over quota. Avatars are already pass-through.
- Map `createSignedUrls` results by index, not `item.path`.
- Invalidate `media:${id}` and `signedUrls:${id}` together.
- Front-camera photos are already mirrored natively; don't flip them again in JS.

### Client code ([ui-and-theme](docs/architecture/ui-and-theme.md))
- Never `Alert.alert` for a decision — it no-ops on web. Use `<ConfirmModal>`; show errors inline.
- Don't use `KeyboardAvoidingView` (broken under the New Architecture); track keyboard height manually.
- `SafeAreaView` comes from `react-native-safe-area-context`; wrap `<Modal>` content in its own `SafeAreaProvider`.
- No percentage widths inside a ScrollView on iOS — use `flex: 1` + `aspectRatio`.
- Remote images use `expo-image`. `expo-file-system` comes from `expo-file-system/legacy`, native-only.
- Colors come from `useTheme()` — never hardcode the accent in app screens. Text on an accent background uses `onAccentColor` (threshold 0.38 is deliberate). `#555555` is decoration only; readable text is `#888888` or brighter.
- Icon-only touchables need `accessibilityRole="button"` + `accessibilityLabel`.
- Hooks (including the animation hooks) go before any early return. Never mix native and JS drivers on one `Animated.Value`.
- IDs come from `randomUUID()` in `src/lib/uuid.ts` (CSPRNG). Never `Math.random()`.
- Haptics through `src/lib/haptics.ts`; external links through `openLink` (`src/lib/openLink.ts`).
- A failed user-initiated mutation must `toast.show(...)`. A swallowed error goes to `reportError(err, { where, extra })` — never with PII.
- People-search surfaces filter `blockStore.has(id)` and `isDemoAccountId(id)`; member/media/reaction lists don't filter demo accounts.

### Monetization ([monetization](docs/architecture/monetization.md))
- All limits live in `src/lib/tierLimits.ts`; never hardcode one (the capsule cap of 3 is mirrored in SQL with a sync comment).
- Caps key off the capsule **owner's** tier; gates go through `proGateHit` (owner sees upgrade, guest sees explain-only).
- `isPro` is UI-only. While `useEntitlements().loading` is true, never treat the user as free — pick the safe shape from the table in the doc.
- Never recreate the `Capsule Pro` entitlement in RevenueCat without updating `PRO_ENTITLEMENT_OBJECT_ID`.

### Builds and native ([infrastructure](docs/architecture/infrastructure.md))
- Native modules, share extension, Live Activity and custom URL schemes need a dev/EAS build, not Expo Go.
- `eas.json` production must keep `RCT_USE_PREBUILT_RNCORE=0`, or `patches/react-native+0.81.5.patch` silently stops applying.
- Extension target names must never sanitize to `Capsule` (collides with the main target).
- `NSSupportsLiveActivities: true` must stay in `app.json`.
- The App Store reviewer account's password is never committed; scripts read it from the environment.
